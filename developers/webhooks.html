Webhooks

A webhook is an address on a server of yours that Empora sends a signed message to when something changes on your account. A licence renews, a site is deactivated, a payment does not go through, a store stops syncing: your own systems hear about it without asking. Each delivery carries the licence, site, plan or connection as the API returns it, and never a licence key, a store credential or anything about your shoppers.

You set addresses up in your account, under Settings, Other apps, Webhooks.

Adding an address​

  1. Choose Add an address.
  2. Enter an https address on a server of yours, like https://hooks.yourstore.com/empora.
  3. Add a note if it helps, like Slack alert for licence changes.
  4. Choose the events it should hear. At least one.
  5. Choose Add the address. Adding an address makes a signing secret, so Empora asks you to confirm it is you if your last sign-in is more than 10 minutes old, and with two-factor on, for a code as well.

Empora shows the signing secret, which starts whsec_, and sends a test straight away. Copy the secret into your server: it is how your side proves a delivery came from Empora. Within 10 minutes of signing in you can see it again with Signing secret, and after that Empora asks you to confirm first.

Addresses Empora refuses​

Empora checks the address when you add it and again before every send. It refuses eight kinds:

RefusedWhy
Anything but httpsEvery delivery is signed, and a signature is only worth something over https
A user name or password in the addressThe signature already proves the sender, so the address needs none
A port other than 443 or 8443Empora sends to no other ports
The machine itself (localhost, 127.0.0.1, ::1)That is the server the address runs on, not one on the internet
A private, link-local, shared or multicast addressSuch as 10.0.0.5, 192.168.1.20, 169.254.169.254 or 100.64.0.1. No one online can reach them
A name that works only inside a networkNames ending in .local, .internal, .lan, .home or .corp
One of Empora's own addressesAnything on aoneahsan.com. Point it at a server of yours
A name that points to any of the aboveEmpora looks the name up and refuses it when any answer is one of those addresses

The last check also runs at send time, and Empora connects to exactly the address it checked, so a name cannot be pointed somewhere private between the check and the send. Numeric forms such as 2130706433 or 0x7f.1 are read as the address they are.

Each refusal says which rule it broke. An address on your WooCommerce store's own domain is fine, as long as it is public and on https.

So one change sends one event, once, to every address that hears it. subscription.canceled and its status value are spelt canceled, with one l, exactly as they arrive; match that spelling in your code.

What a delivery looks like​

Each delivery is a POST with a JSON body and these headers:

POST /empora HTTP/1.1
Host: hooks.yourstore.com
Content-Type: application/json
User-Agent: Empora-Webhooks/1.0
webhook-id: msg_2Kp7vQ9xLm4TzR8wNc3bYh
webhook-timestamp: 1795252443
webhook-signature: v1,Kd3/gYx/g1NffbIUFddudPFyF9nek+pZwDttre1DASo=

{"type":"licence.renewed","timestamp":"2026-11-21T09:14:03Z","data":{"id":4182,"plan":"professional","status":"active","expires_at":"2027-11-21T09:14:03+00:00","max_sites":1,"active_sites":1,"created_at":"2025-11-21T09:12:40+00:00"}}
PartHolds
webhook-idOne id per event. It stays the same on every retry and on Send again, so your side can ignore a repeat
webhook-timestampWhen this attempt was signed, in seconds since 1970 (UTC)
webhook-signaturev1, and a base64 HMAC-SHA256. For 24 hours after you replace the secret, two entries separated by a space
typeThe event name
timestampWhen the event happened, in UTC
dataThe licence, site, plan or connection, with the same fields the API returns

This follows Standard Webhooks, so any library written for it verifies an Empora delivery as it is.

Checking the signature​

Check every delivery before you act on it. The signature is an HMAC-SHA256 of three things joined by full stops: the webhook-id, the webhook-timestamp, and the body exactly as it arrived. The key is the part of your secret after whsec_, base64-decoded.

Three rules make a check correct:

  • Use the raw body. Parsing the JSON and encoding it again changes the bytes, and the signature no longer matches.
  • Compare in constant time, and accept a match with any v1 entry: after you replace the secret, two arrive.
  • Refuse an old timestamp. Five minutes either side of your clock is the usual window. Empora signs each attempt when it sends it, so a retry carries a fresh timestamp.

Node​

No package needed. Node's own crypto does the work.

verify-empora.mjs
import { createHmac, timingSafeEqual } from 'node:crypto';

/**
 * Checks one Empora delivery. `rawBody` is the request body exactly as it arrived,
 * before any JSON parsing. Returns true only for a genuine, recent delivery.
 */
export function verifyEmporaDelivery({ rawBody, headers, secret, toleranceSeconds = 300 }) {
  const id = headers['webhook-id'];
  const timestamp = headers['webhook-timestamp'];
  const signatures = headers['webhook-signature'];
  if (!id || !timestamp || !signatures) return false;

  const age = Math.abs(Math.floor(Date.now() / 1000) - Number(timestamp));
  if (!Number.isFinite(age) || age > toleranceSeconds) return false;

  const key = Buffer.from(secret.replace(/^whsec_/, ''), 'base64');
  const expected = createHmac('sha256', key)
    .update(`${id}.${timestamp}.${rawBody}`)
    .digest();

  // Two signatures arrive for 24 hours after you replace the secret: accept either.
  return signatures.split(' ').some((entry) => {
    const [version, value] = entry.split(',');
    if (version !== 'v1' || !value) return false;
    const given = Buffer.from(value, 'base64');
    return given.length === expected.length && timingSafeEqual(given, expected);
  });
}

A small server that uses it, with Node's own http, so the body is never parsed before the check:

server.mjs
import { createServer } from 'node:http';
import { verifyEmporaDelivery } from './verify-empora.mjs';

createServer((req, res) => {
  const chunks = [];
  req.on('data', (chunk) => chunks.push(chunk));
  req.on('end', () => {
    const rawBody = Buffer.concat(chunks).toString('utf8');
    const ok = verifyEmporaDelivery({ rawBody, headers: req.headers, secret: process.env.EMPORA_WEBHOOK_SECRET });
    if (!ok) {
      res.writeHead(401).end();
      return;
    }
    const event = JSON.parse(rawBody);
    // Hand the event to a queue here, and answer straight away.
    res.writeHead(204).end();
  });
}).listen(8080);

With Express, read the body with express.raw({ type: 'application/json' }) on this route, so req.body is still the raw bytes when you check it.

PHP​

Plain PHP 8.1, nothing to install:

verify-empora.php
<?php
/**
 * Checks one Empora delivery. $raw_body is the request body exactly as it arrived,
 * before json_decode(). Returns true only for a genuine, recent delivery.
 */
function empora_verify_delivery(string $raw_body, string $id, string $timestamp, string $signatures, string $secret, int $tolerance = 300): bool
{
    if ($id === '' || $signatures === '' || ! ctype_digit($timestamp)) {
        return false;
    }
    if (abs(time() - (int) $timestamp) > $tolerance) {
        return false;
    }

    $key = base64_decode(preg_replace('/^whsec_/', '', $secret), true);
    if ($key === false) {
        return false;
    }
    $expected = base64_encode(hash_hmac('sha256', $id . '.' . $timestamp . '.' . $raw_body, $key, true));

    // Two signatures arrive for 24 hours after you replace the secret: accept either.
    foreach (explode(' ', $signatures) as $entry) {
        [$version, $value] = array_pad(explode(',', $entry, 2), 2, '');
        if ($version === 'v1' && hash_equals($expected, $value)) {
            return true;
        }
    }

    return false;
}

On a standalone PHP endpoint, read the body with file_get_contents('php://input') and the headers from $_SERVER['HTTP_WEBHOOK_ID'], $_SERVER['HTTP_WEBHOOK_TIMESTAMP'] and $_SERVER['HTTP_WEBHOOK_SIGNATURE'].

On your WordPress site​

If the receiver is your WooCommerce site, a small plugin or your theme's functions.php can register a REST route for it. WP_REST_Request::get_body() returns the raw body, which is what the check needs. Keep the secret in wp-config.php, not in the database.

empora-webhook-receiver.php
<?php
/**
 * Plugin Name: Empora webhook receiver
 * Description: Receives signed deliveries from Empora at /wp-json/empora-hooks/v1/receive.
 */

// In wp-config.php: define( 'EMPORA_WEBHOOK_SECRET', 'whsec_…' );

require_once __DIR__ . '/verify-empora.php';

add_action( 'rest_api_init', function () {
    register_rest_route( 'empora-hooks/v1', '/receive', array(
        'methods'             => 'POST',
        'permission_callback' => function ( WP_REST_Request $request ) {
            return empora_verify_delivery(
                $request->get_body(),
                (string) $request->get_header( 'webhook-id' ),
                (string) $request->get_header( 'webhook-timestamp' ),
                (string) $request->get_header( 'webhook-signature' ),
                (string) EMPORA_WEBHOOK_SECRET
            );
        },
        'callback'            => function ( WP_REST_Request $request ) {
            $event = json_decode( $request->get_body(), true );
            // Remember $request->get_header( 'webhook-id' ) and skip one you have seen.
            // Schedule the slow work, for example with as_enqueue_async_action(), and answer at once.
            return new WP_REST_Response( null, 204 );
        },
    ) );
} );

The address to add in Empora is then https://yourstore.com/wp-json/empora-hooks/v1/receive. A refused signature answers 401 from WordPress, which Empora counts as a failure and tries again.

Answering a delivery​

Answer with any 2xx within 10 seconds. Do the slow work afterwards, from a queue, because Empora waits no longer.

  • A 3xx counts as a failure. Redirects are never followed, so give Empora the final address.
  • Empora keeps only the status and the first 4 KB of your answer for the delivery log, never its headers.
  • 410 Gone turns the address off at once. Use it when the address is retired for good.

Retries and turning off​

A delivery that fails is tried again after 5 seconds, 5 minutes, 30 minutes, 2 hours, 5 hours and twice after 10 hours: eight tries in all. Each retry carries the same webhook-id.

When an address has failed for 5 days in a row, Empora turns it off and emails you with its last answer. Nothing is sent to it after that. Choose Turn on when it answers again: Empora sends a test first, and the address stays off unless the test gets a 2xx.

Pause, test, send again​

  • Pause stops deliveries to an address without removing it. Events raised while it is paused wait in its deliveries, and go out, oldest first, when you turn it back on (Empora sends a test first). Events older than the 30-day log are not kept. An address that Empora turned off after failures does not collect events: those are listed as skipped, and Send again sends any one of them.
  • Send a test sends a webhook.test event to the address, whatever its state. Its answer shows under Deliveries.
  • Deliveries lists what went to an address in the last 30 days: the event, when, the answer, how many tries, and the next try. Send again sends an event again with the same webhook-id and a fresh set of tries.
  • Remove deletes the address. Nothing more goes to it.

Changing an address's URL or events keeps its signing secret.

Replacing the signing secret​

Replace the secret makes a new one. For the next 24 hours each delivery carries two signatures, one from each secret, so you can swap the secret on your server without missing a delivery. After 24 hours, only the new one signs. Replacing needs the same confirmation as showing it.

How many addresses you can have​

Free allows 3 webhook addresses, Starter, Professional and Business allow 20, and Enterprise allows 40. Paused and turned-off addresses count; removing one frees its place.
